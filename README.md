### 프로젝트 개요

* 기존 채용 플랫폼의 키워드 기반 추천 방식은 개별 기술의 실제 활용 범위와 직무 간 차이를 세밀하게 반영하는 데 한계가 있다.

    e.g. `통계학`, `Python`, `PyTorch` 키워드 등록 &rarr; 데이터 분석·AI 직무뿐 아니라 백엔드 개발, 정보보안, 데이터 엔지니어 직무를 함께 추천

* LLM이 후보자의 역량 범위와 채용 공고의 실질적인 업무 내용을 함께 해석할 수 있다는 점에 착안하여, 직무 적합성을 평가하고 그 결과를 자동으로 전달하는 프로젝트를 기획하였다.

* 증가하는 AI 자동화 수요에 대응하고자 n8n을 학습하였으며, 이를 활용해 채용 공고 수집·평가·메일 발송 과정을 하나의 자동화 워크플로우로 구현하였다.

* [잡코리아](https://www.jobkorea.co.kr)에 등록된 1000대 기업의 채용 공고를 대상으로 하였다.

    * 이미지가 포함된 경우 멀티모달 LLM을 활용하여 이미지 내 텍스트를 추출하였다.
      
    * 표·도식 등의 구조가 최대한 유지되도록 결과를 마크다운 형식으로 출력하게 하였고, n8n 무료 체험판에서 제공된 OpenAI 사용 크레딧을 활용하기 위해 `gpt-4.1-nano` 모델을 사용하였다.
      
    * 적용한 프롬프트는 다음과 같다.

        ```text
        # 작업
        제공된 채용 공고 이미지들의 텍스트를 OCR하고,
        문서에 실제로 나타난 구조와 계층을 유지해 마크다운 형식으로 정리하라.
        
        # 규칙
        - 항목명이나 문서 형식을 미리 가정하지 말고,
        이미지에서 확인되는 제목·소제목·표·목록·본문 구조를 스스로 판단한다.
        - 이미지에 있는 정보만 추출하며, 누락된 내용을 추측하거나 보완하지 않는다.
        - 원문의 순서, 항목 간 관계, 줄바꿈과 목록 구조를 가능한 한 유지한다.
        - 여러 이미지가 하나의 문서로 이어지면 자연스럽게 통합하되,
        중복 내용은 반복하지 않는다.
        - 버튼, 아이콘, 로고, 장식 요소, 배너, QR코드 등 문서 내용과 무관하거나
        글로 표현할 수 없는 이미지는 무시한다.
        - 문서 내용과 무관하거나 글로 표현할 수 없는  인터페이스 요소는 무시한다.
        - 읽을 수 없는 부분은 임의로 해석하지 말고 `[판독 불가]`로 표시한다.
        - 설명이나 OCR 과정은 출력하지 않고 결과만 출력한다.
        - 유의미한 문서 내용이 없으면 정확히 `유의미한 내용이 없습니다.`라고 출력한다.
        
        # 출력 형식
        이미지에서 확인된 문서 구조를 반영한 마크다운
        ```


* 추출한 본문과 이미지 내용을 하나의 마크다운 문서로 통합한 뒤 `Basic LLM Chain` 노드에 입력하였다. LLM이 채용 공고와 보유 역량을 비교하여 직무 적합성을 평가하고 지원 추천 여부와 판단 근거를 요약하도록 구성하였으며, `Structured Output Parser` 노드를 연결하여 평가 결과가 일관된 형식으로 출력되도록 하였다.

        ```text
        # 작업
        제공된 채용 공고를 검토하여 후보자의 역량과 연관되는 직무가 포함되어 있는지 판단하고,

        # 후보자 역량
        - 통계학 석사
        - Python 기반 데이터 전처리·분석, 통계 모델링, 머신러닝
        - 분류, 회귀, 시계열 분석·예측
        - 교차검증, 앙상블, 모델 성능 평가
        - PyTorch 기반 딥러닝
        - 이미지 분류, 자연어 처리, 시계열 예측
        - AI 코딩 에이전트를 활용한 임베딩·벡터 검색 기반 추천 시스템의 구현, 수정, 디버깅
        및 배포 경험
        - n8n 기반 업무 자동화 워크플로우 설계·구현 경험
        
        # 역량 범위
        - Python은 데이터 분석·통계·머신러닝·딥러닝 용도로 사용했으며,
        Python 활용 경험을 백엔드 개발 또는 일반 소프트웨어 엔지니어링 경험으로
        확대 해석하지 않는다.
        - AI 코딩 에이전트를 활용해 백엔드 관련 기능을 구현한 경험은 있으나,
        이를 독립적인 백엔드 개발 역량으로 평가하지 않는다.
        - AI 코딩 에이전트 활용 경험은 요구사항을 기능으로 구체화하여 결과물을 완성하는
        AI 활용 역량으로 평가한다.
        
        # 판단 규칙
        - 입력은 채용 공고의 메타데이터, 본문 및 이미지 OCR 결과이며,
        일부 정보가 없거나 판독되지 않을 수 있다.
        - 공고에 포함된 모든 직무를 확인하고,
        직무명뿐 아니라 담당 업무, 필수 지원 자격 및 우대 사항을 후보자의 역량과 비교한다.
        - 가장 연관성이 높은 직무명을 공고에 기재된 표현 그대로 밝히고,
        연관되는 후보자 역량과 판단 근거를 설명한다.
        - 다음 유형을 구분하여 판단한다.
        - 후보자의 하드 스킬과 직접적으로 연관되는 직무
        - 후보자의 기존 경험을 전이하여 수행할 가능성이 있는 직무
        - 특정 하드 스킬보다 일반 역량이나 소프트 스킬이 중심인 직무
        - 후보자의 역량과 관련성이 낮거나 필수 자격을 충족하지 못하는 직무
        - 직무명에 `데이터`, `AI`, `Python` 등의 단어가 포함되어 있다는 이유만으로
        적합하다고 판단하지 않는다.
        - 필수 자격을 명백히 충족하지 못하는 경우 이를 추천 결과에 반영한다.
        - 우대 사항을 충족하지 못하는 것과 필수 자격을 충족하지 못하는 것을 구분한다.
        - 공고 또는 후보자 역량에 명시되지 않은 정보는 추측하거나 보완하지 않는다.
        - 공고 정보가 부족하여 적합성을 판단할 수 없으면 `판단 불가`로 결론 내리고,
        부족한 정보를 설명한다.
        - 최종 결론은 `추천`, `조건부 추천`, `비추천`, `판단 불가` 중 하나로 명확히 제시한다.
        - 회사를 명시한다.
        - 모든 문장은 격식 있는 `-합니다/-됩니다`체로 작성한다.
        
        # 출력
        유효한 JSON만 출력한다. 마크다운 코드 블록이나 JSON 외의 설명은 출력하지 않는다.
        
        {"summary":"결론을 먼저 밝히고, 가장 연관성이 높은 직무명과
        후보자 역량의 연결 근거, 자격 요건상 주의점을 2~4문장으로 작성한다."}
        ```

  * 리뷰 측면에서 대형 IP, 음향, 부정 키워드의 중요도가 높게 나타났다.
 
* SHAP:

  * 예산이 클수록 국내 특화와는 거리가 먼 것으로 나타났다. 이는 예산이 큰 영화가 국내에서 흥행하지 못해서가 아니라, 어느 나라에서든 흥행하는 보편적 콘텐츠일 가능성이 높기 때문이다.
 
  * 해외에 비해 국내 시장은 스릴러 장르를 선호한다.
 
  * 대형 IP 키워드는 국내 특화와는 거리가 먼 것으로 나타났다. 높은 예산과 일맥상통하게, 대형 IP일수록 국내 한정 흥행이 아닌 글로벌 흥행으로 이어지는 경우가 많기 때문이다.
 
  * 특이하게, 부정적 감성 키워드는 한국 특화에 긍정적 영향을 미쳤다.
 
* 결론:

  * 해외와 국내 모두 액션 장르가 강세지만, 국내 시장 공략에는 범죄·스릴러 요소의 명확한 반영이 요구된다.

  * 많은 예산이 투입된 시각 효과는 보편적으로 선호되는 영역이며, 국내 시장을 겨냥하려면 청각적 요소에 대한 추가적인 투자가 필요하다.
 
  * 대형 IP는 국내 특화형과 거리가 멀다. 반대로 글로벌 시장에 대응하려면 검증된 IP가 필수적이다. 글로벌 시장을 목표로 한다면 초기 기획 단계에서 장기적 IP 투자와 트랜스미디어 전략 수립이 권장된다.
 
  * 리뷰의 양극화는 논쟁과 호기심을 유발해 의외의 성공으로 이어지는 경향이 있다 ([Louposet al.](https://link.springer.com/article/10.1007/s11002-023-09665-8)). 부정 키워드가 국내 특화율을 높인 것은 국내 시장이 화제성에 민감하기 때문이다. 국내 시장을 노린다면 버즈 마케팅으로 바이럴 효과를 극대화할 필요가 있다.

  * 유형별 신고 건수의 합이 총 신고 건수와 일치하지 않았으며, 이는 [부산광역시 소방 출동 정보 API](https://www.data.go.kr/data/15087824/openapi.do)와도 일치하지 않았다.
    
  * `OUTER JOIN`이 아닌 `INNER JOIN` 방식으로 결합된 소방·기상 데이터가 제공되어, 신고가 일어나지 않은 날짜의 정보는 데이터에서 제외되었다. 이로 인해 신고 건수가 0인 날은 예측할 수 없었다.
    
  * 평가 데이터 역시 신고가 있던 날만 포함되었다.
  
### 분석 방안

* 기상 자료의 결측값은 날짜와 지역을 고려하여 보간하였다.

* 자료의 비정규성을 고려해 Spearman 상관 계수를 사용하여 기상 변수와 유형별 신고 건수 사이의 상관 관계를 탐색하였다.

* 데이터 유출에 주의하며 `TimeSeriesSplit`과 `optuna`를 통해 `LGBMRegressor`, `RandomForestRegressor`, `XGBRegressor`의 최적 하이퍼파라미터를 탐색하였다.

* 각 모형의 예측값을 Meta Feature로 활용해 `Ridge` 회귀 기반의 앙상블을 수행하였으며, `optuna`를 통해 교차 검증 RMSE를 최소화하는 `alpha`를 탐색하였다.

### 분석 결과

* 수상하지 못하였으며, 순위는 공개되지 않았다.

* 상관 분석:

  * `구조` 신고 건수는 기온, 습도, 풍속과 약한 양의 상관 관계를 보여, 태풍과의 연관성이 추정된다.

  * `화재` 신고 건수는 습도와 약한 음의 상관 관계를 보여, 건조한 기후 조건이 화재 발생에 영향을 미친 것으로 해석된다. 기온과는 약한 양의 상관 관계를 나타내는데, 이는 화재로 인한 기온 상승이 반영된 결과일 수 있다.

  * `구급` 및 `기타` 유형의 신고 건수는 기상 변수와 유의미한 상관 관계를 보이지 않았다.

* 총 신고 건수 예측: 평균과 표준편차가 약 2, 중간값이 1인 목표 변수에 대해 약 1.05의 평가 RMSE를 기록하였다.

* 변수 중요도:

  * 강수량과 풍속 관련 변수의 중요도가 높게 나타나, 상관 분석 결과와 일관되게 태풍의 영향을 크게 받는 것으로 추정된다.

  * 신고 건수가 전반적으로 적고, 날짜와 무관하게 지역 내부에서 일정한 경향을 보여 `TargetEncoder`를 적용한 범주형 변수의 목표 기반 통계량이 높은 중요도를 보였다. 이 중 `sub_address`(읍·면·동)은 핵심 변수로 작용했다.

  * 지역 규모를 나타내는 변수들, 특히 읍·면·동별 세대 수는 신고 건수 예측에서 중요한 변수로 작용하였다.

* SHAP(SHapley Additive exPlanations):

  * 상관 분석과 변수 중요도 결과와 일관되게, 강수량과 풍속은 신고 건수 변화에 강한 영향을 미치는 요인으로 나타났다.

  * 읍·면·동 단위에서 신고 특성이 뚜렷하게 나타났으며, 인구 구성 지표는 위험 예측에 있어 매우 유의미한 변수로 작용하였다.

### 개선점

* 데이터 유출 기준을 명확하게 세우지 못하였다. 예를 들어, 예측 시 당일 기상 자료는 사용할 수 있었지만, 당일 인구 정보의 사용 가능 여부는 불분명하였다. 이러한 이유로 일부 파생 변수의 시점 기준이 일관되지 않았으며, 당시 리더십을 발휘해 이를 명확히 통일했다면 더 나은 결과로 이어질 수 있었을 것이다.

* 신고가 없는 일자의 기상 자료를 확보했다면, 조건부 예측이 아닌 전반적인 신고 건수 예측이 가능했을 것이다. 그러나, 추가 정보를 얻기 위해 접근한 [부산광역시 소방 출동 정보 API](https://www.data.go.kr/data/15087824/openapi.do)는 날짜별 조회가 불가능하였고, 저장 구조가 자주 변경되어 실질적인 활용이 어려웠다.

* 동일한 날짜라도 여러 지역이 행으로 구분되어 있기 때문에, `TimeSeriesSplit`은 시계열성을 보장하지 못한다. `Scikit-Learn`의 `BaseCrossValidator`를 기반으로 지역 단위와 시계열성을 동시에 보존하는 별도의 클래스를 구현하는 것이 바람직하였다.

### 분석 개요

* 자갈의 암석 종류는 콘크리트와 아스팔트의 품질에 직접적인 영향을 미치므로, 정확한 분류가 요구된다.

* 기존 수작업 방식은 많은 시간과 비용이 소요될 뿐 아니라, 검사자의 숙련도에 따라 정확도에 편차가 발생하는 한계가 있다.

* 건설용 자갈 이미지를 활용해 암석 종류를 분류하는 AI 알고리즘 개발을 목표로 한다.

* 평가 기준: Macro F1 Score

### 분석 방안

* [ImageNet](https://www.image-net.org/)에서 검증된 ConvNeXt Base, Swin V2 Small, EfficientNet V2 Medium을 기반 모형으로 활용하였다. 세 모형 모두 사전학습된 가중치를 초기값으로 사용해 학습을 진행하였다.

* 더 많은 파라미터를 가진 모형이 성능 면에서 유리할 것으로 보였으나, 제한된 연산 자원으로 인해 경량 모형들을 다수 활용한 앙상블 전략을 선택하였다.

* 각 모형의 OOF(Out-of-Fold) 예측 결과를 활용하여 교차 검증 손실 함수를 최소화하는 가중치를 도출하였다.

* 자원 효율 향상을 위해 AMP(Automatic Mixed Precision) 기법을 활용하였다.

* 클래스 불균형을 고려해, 학습 및 검증 데이터가 동일한 클래스 비율을 갖도록 분할한 후, 손실 함수로 Focal Loss를 사용하였다. Focal Loss와 Oversampling을 함께 적용한 실험에서 성능 저하가 발생하여, 모형 개발 과정에서 해당 전략은 제외하였다.

* 다양한 환경에서 촬영된 자갈의 색상, 질감, 위치 등의 변화를 모형이 인식할 수 있도록, 회전, 노이즈 추가 등 다양한 데이터 증강(Data Augmentation) 기법을 적용하였다.

### 개선점

* 상위권 경쟁자들과 동일한 기반 모형, 학습률(Learning Rate), 스케줄러(Scheduler)를 적용하였으나, 학습 속도가 느려 충분한 Epoch을 확보하지 못하였다.

* 상위권 경쟁자들의 실험에 따르면, Focal Loss보다 WCE Loss(Weighted Cross-Entropy Loss)가 소폭 더 안정적인 성능을 보였으며, 해당 문제에서는 WCE Loss가 더 적합한 손실 함수로 판단된다.
